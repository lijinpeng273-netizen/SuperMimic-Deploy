## 4. 新策略每次推理具体输入什么

### 4.1 单帧观测：72 维

实现位置：`src/h1_deploy/deploy/core.py` 的 `DeployCore.observation()`，以及新增 `deploy/blinkmimic.py` 的 `BlinkReference.relative_pose()`。

下表使用 Python 左闭右开切片：

| 切片 | 维度 | 内容 | 单位/坐标系 |
|---|---:|---|---|
| `[0:19]` | 19 | 当前关节角减默认关节角 `q-q0` | rad，H1 策略关节顺序 |
| `[19:38]` | 19 | 当前关节角速度 `dq` | rad/s |
| `[38:41]` | 3 | 骨盆角速度 gyro | 骨盆局部坐标系，rad/s |
| `[41:44]` | 3 | 投影重力 | 骨盆局部坐标系 |
| `[44:63]` | 19 | 上一次网络最终动作 `last_action` | 包含参考动作跳连；不是限幅后的关节目标 |
| `[63:69]` | 6 | 当前参考骨盆相对实际骨盆的旋转 | 六维旋转表示 |
| `[69:72]` | 3 | 当前参考骨盆相对实际骨盆的位置 | 骨盆局部坐标系，m |

设实际骨盆姿态为 `R`、位置为 `p`；第 `f` 帧参考姿态、位置为 `R_ref[f]`、`p_ref[f]`：

```text
relative_rotation = R.T @ R_ref[f]
relative_position = R.T @ (p_ref[f] - p)
```

六维旋转取旋转矩阵的前两列，再按行展开。例如单位旋转矩阵对应：

```text
[1, 0, 0, 1, 0, 0]
```

不能把这 9 维全部补零，也不能沿用旧策略的“位置 3 维在前、旋转 6 维在后、拼在 goal 末尾”的方式。

### 4.2 历史帧：10 × 72 = 720 维

新策略的历史排列是：

```text
[第 t-9 帧完整的 72 维,
 第 t-8 帧完整的 72 维,
 ...,
 第 t 帧完整的 72 维]
```

第一次推理将当前帧重复填满 10 个历史位置；之后每次移除最旧一帧、追加最新一帧。

原策略仍保留按观测项展开的 630 维排列。两条分支由 `policy_format` 选择，没有全局修改旧策略的历史格式。

`switch_clip()` 继续保持历史和上一动作，用于策略待机与动作播放之间的衔接；原来固定 PD 准备阶段创建新 `DeployCore`、重置历史的行为保持不变。

### 4.3 未来目标：10 × 53 = 530 维

实现位置：`src/h1_deploy/deploy/blinkmimic.py` 的 `BlinkReference.goal()`。

当前参考帧为 `f` 时，取 `f+1` 到 `f+10`。超出动作末尾的索引重复使用最后一帧。

每个未来参考帧的 53 维定义：

| 单帧切片 | 维度 | 内容 |
|---|---:|---|
| `[0:3]` | 3 | 未来根位置相对当前参考根位置的位移，转换到当前参考航向坐标系 |
| `[3:9]` | 6 | 未来根旋转相对当前参考航向的六维表示 |
| `[9:12]` | 3 | 未来根线速度，表达在该未来帧的骨盆局部坐标系 |
| `[12:15]` | 3 | 未来根角速度，表达在该未来帧的骨盆局部坐标系 |
| `[15:34]` | 19 | 未来关节角 `q_ref`，绝对关节角，不减默认角 |
| `[34:53]` | 19 | 未来关节角速度乘以 `0.1` |

其中，位置和旋转所用的航向来自**当前参考姿态**，不是机器人的当前姿态。目标向量本身只由参考动作生成；机器人的偏差通过 obs 中的相对位姿反馈。

速度的处理也按训练定义重建：

```text
dt = 0.02 s
内部帧的线速度/关节速度 = (后一帧位置 - 前一帧位置) / (2*dt)
首尾帧                         使用单边差分
角速度                         对旋转矩阵做 SO(3) 差分
```

因此新策略从 `joint_pos`、`root_pos`、`root_quat_wxyz` 重新计算目标，不直接复用旧 NPZ 内的 `goal[T,48]`，也不直接采用里面预存的速度数组。派生数据按 Clip 缓存；切换到另一 Clip 时会重新构建。

旧 NPZ 的 `goal[T,48]` 仍被保留，因为现有 Clip 加载、其他工具以及旧策略使用它。**不要手工把 NPZ 的 goal 表改成 53 维**：当前磁盘格式仍是旧格式，新格式在运行时适配。

### 4.4 归一化与参考动作跳连

实现位置：`src/h1_deploy/policy/blinkmimic.py`。

观测按每帧 72 维归一化，goal 按 530 维归一化：

```text
x_normalized = (x - mean) / sqrt(var + 0.01^2)
```

`mean`、`var`、`count` 来自 `pi.obs_norm.*` 和 `pi.goal_norm.*`。部署时冻结，不重新采样统计，不以零均值、单位方差替代。`count` 为兼容检查点保留，不在部署中更新。

输入 obs 的 `dq` 和 gyro 不额外乘训练源码中某些辅助函数列出的 `0.1`、`0.25`；已对照实际策略调用路径，使用原始观测后交给 RunningNorm。goal 中关节速度乘 `0.1` 则属于上述目标定义，必须保留。

网络结构为：

```text
goal[530]
  -> RunningNorm
  -> MLP: 530 -> 2048 -> 1024 -> 512 -> 256 -> 32
  -> tanh，得到 z[32]

obs[720]
  -> reshape 成 [10,72]
  -> 每帧 RunningNorm
  -> 按帧展开回 720 维

concat(z, obs) = 752 维
  -> MLP: 752 -> 2048 -> 1024 -> 512 -> 256 -> 19
  -> residual_action[19]
```

MLP 隐藏层激活函数为 ELU。当前检查点启用了参考动作跳连：

```text
q_ref_next = 原始未归一化 goal[15:34]
action = residual_action + (q_ref_next - ref_q0) / ref_alpha
q_target_raw = default_joint_pos + action_scale * action
```

这份权重中 `ref_q0 = default_joint_pos`、`ref_alpha = action_scale = 0.25`，因此在目标限幅前等价于：

```text
q_target_raw = q_ref_next + 0.25 * residual_action
```

后面仍执行原仓库的关节目标/力矩限制。`last_action` 回馈的是完整 `action`，不是单独的残差，也不是 `q_target`。

### 6.2 PD 与动作参数：本次没有改变数值

`last.pt` 的 PD、默认关节角和动作缩放与本部署模型一致，因此沿用原数值。

策略阶段读取 `deploy_artifacts/last/deploy_config.json` 的 `kp`、`kd`、`default_joint_pos`、`action_scale`、`effort_limit` 等字段。导出基础数值来自 `src/h1_deploy/robots/h1.py`；新检查点校验会核对训练记录与这些常量。

| 关节组（左右相同） | KP | KD | 动作缩放 |
|---|---:|---:|---:|
| hip_yaw | 150 | 2 | 0.25 |
| hip_roll | 150 | 2 | 0.25 |
| hip_pitch | 150 | 2 | 0.25 |
| knee | 200 | 4 | 0.25 |
| ankle | 40 | 2 | 0.25 |
| torso | 300 | 3 | 0.25 |
| shoulder_pitch / roll / yaw | 100 | 2 | 0.25 |
| elbow | 50 | 2 | 0.25 |

默认关节角按策略顺序是：

```text
左腿 [0, 0, -0.4, 0.8, -0.4]
右腿 [0, 0, -0.4, 0.8, -0.4]
躯干 [0]
左臂 [0, 0, 0, 0]
右臂 [0, 0, 0, 0]
```

策略周期仍是 `control_dt=0.02 s`。配置中的 `sim_dt=0.005`、`decimation=4` 描述训练模型的时间步设置；DDS 仿真器的物理步长由它自己的 `--dt` 决定，G2 使用 1 ms PD 仿真，不能把这几个时间步混为一个参数。

固定 PD 准备阶段的 KP 仍使用 runner 的站立常量。后续实机调试已将固定 PD 的 KD 默认改为复制当前 `deploy_config.json` 的 `kd`，因此 `last` 默认手臂为 2、腰部为 3。`--stand-arm-kd`、`--stand-waist-kd` 仅在显式传入时覆盖固定 PD，对策略 KD 不产生影响。

## 10. 当前文件是否齐全，有什么尚未提供
