# 新策略 last：dance 的 G2、G3 与 standby 评估简析

更新日期：2026-11-13。策略为 `last`，动作 `dance` 完整播放约 23.62 秒。

数据来源：[G2 报告](SIM2SIM_dance_new_last.md)、[G3 报告](SIM2SIM_dance_last.md)、[standby 报告](standby_dance_last.md)；统计核对了 [G2 JSON](sim2sim_dance_new_last.json) 和 [G3/standby JSON](sim2sim_dance_last.json)。不同报告的 `not run` 只表示该报告未收录，不能据此判断其他批次没有测试。

## 1. 总体结果

| 测试 | 主要检查什么 | 本次结果 |
|---|---|---|
| G2 | 动作跟踪，以及延迟、KP、质量、摩擦扰动下的速度和力矩余量 | 100 个工况均完成、无跌倒；16 个触发保护；7 个变体全部 FAIL |
| G3 | 固定 PD 接入策略、动作循环、策略退出及不同支撑条件 | 29 个工况中 28 个未跌倒、1 个退出后跌倒；29 个均触发保护；汇总门槛全部 FAIL |
| standby | 策略控制下的前待机 → 播放 → 后待机，以及播放前稳定性 | 72 个工况均完成、无跌倒，但全部触发保护，0/72 通过 |

**共同限制：这些评估记录保护触发后仍继续仿真；实际 DDS/实机 runner 收到同类 `DeployCore.abort` 会进入 DAMP。因此，“最终完成、没有跌倒”不能等同于真实部署能连续运行。**

## 2. G2：动作本身及扰动适应性

默认 G2 从首帧姿态、落地静止状态开始，采用 50 Hz 策略与 1 kHz PD。默认网格覆盖延迟 0/5/10/20 ms、KP 倍率 0.85/1/1.15、附加质量 0/1.8 kg、摩擦 0.6/1.0；其他变体使用较小网格。

| 变体 | 用途 | 触发保护的工况 | 主要结论 |
|---|---|---:|---|
| `g2` | 默认目标力矩限幅系数 1.5 | 1/48 | 名义工况高力矩时间最坏占 5.82%，超过 1% 要求 |
| `g2_settle500` | 地面固定 PD 保持首帧 0.5 秒，再接入策略 | 8/8 | 接管瞬态恶化，出现速度/姿态超限 |
| `g2_hardclip` | 把目标关节角裁剪到硬限位 | 0/4 | 高力矩时间仍达 6.24%，未解决余量问题 |
| `g2_hr88` | 将髋滚转力矩上限设为 88 Nm | 0/16 | 高力矩时间仍达 5.82% |
| `g2_f1.0` | 目标力矩限幅系数 1.0 | 0/8 | 高力矩时间仍达 5.87% |
| `g2_f0.5` | 目标力矩限幅系数 0.5 | 7/8 | 高力矩时间降至 0.21%，但速度保护频繁触发 |
| `g2_noclamp` | 取消目标力矩限幅，保留仿真电机饱和 | 0/8 | 高力矩时间仍达 5.85% |

这里“高力矩时间”指任一关节的 **PD 需求力矩超过上限 90%** 的时间占比，表内取名义工况最坏值；它不等于电机实际输出超过硬上限。G2 最终判定主要检查 KP=1、附加质量=0 的名义工况。

默认 G2 的 8 个名义工况均无保护触发，平均关节 RMSE 约 **0.118 rad（6.76°）**；默认变体的主要问题是力矩余量。`f0.5` 的平均误差升至约 0.161 rad，因此不能简单通过大幅降低限幅系数解决问题。地面 `settle500` 也不能代替实机悬空 PD 过渡的验证。

## 3. G3：启动、循环和退出过渡

基本流程为：**4 秒固定 PD 插值 → 1 秒 HOLD → 策略播放 → 退出过渡**。默认准备阶段有支撑，策略开始时撤去支撑，退出时恢复。

| 测试项 | 用途 | 本次结果 |
|---|---|---|
| `main` | 比较限幅系数 0.5/1.0/1.5 和延迟 0/20 ms | 6 个均未跌倒，但全部触发保护 |
| `start_ramp` | HOLD 末尾用 1 秒渐变到训练 KP/KD | 2 个均触发保护，启动问题未改善 |
| `loop60` | 保持策略历史，循环动作 60 秒 | 2 个均未跌倒，但均触发保护；本次循环的是 dance，并非静止站立 |
| `cosine`、`blend_lat2` | 检查余弦退出渐变和退出命令延迟 2 ms | 4 个均未跌倒，退出较平滑，但仍有启动保护 |
| `switch_pose`、`switch_last` | 对比直接切末帧姿态和保留最后策略目标的退出方式 | 4 个均未跌倒；直接切末帧姿态的力矩跳变明显更大 |
| `stage_air/band/feet`、`blend_lat2_air` | 比较悬空、释放支撑、脚着地持续支撑及分阶段保护阈值 | 共 10 个均未跌倒，但均触发姿态或关节速度保护 |
| `blend_unsupported_end` | 退出后不恢复支撑，验证固定 PD 能否维持 | 唯一跌倒工况；在总仿真时间 30.14 秒的 END_HOLD 阶段跌倒 |

最值得关注的两点：

- **启动前状态不合适。** 25/29 个工况在策略第 0 步就出现约 27° 的姿态误差；默认工况 HOLD 结束时已倾斜约 27°。这说明应优先检查接管前状态与首帧参考的差异。默认接管力矩跳变约 **55.7 Nm/ms**，增加 KP/KD 渐变也未消除。
- **退出渐变有效，但不能替代平衡或支撑。** 默认线性渐变退出的跳变约 0.1 Nm/ms，直接切末帧姿态则为 **48.3–50.7 Nm/ms**；无支撑退出仍会跌倒。适合保留平滑退出，并确认后续由策略维持平衡或由吊绳承重。

## 4. standby：策略待机与播放衔接

流程为：**前待机 60 秒 → dance 23.62 秒 → 后待机 30 秒**。前后待机均由策略控制，分别使用动作首帧、末帧的静态参考；该测试中策略接管后全程不提供吊绳支撑。

每种配置测试 36 个工况：延迟 0/10/20 ms × 摩擦 0.6/1.0 × KP 倍率 0.85/1/1.15 × 附加质量 0/1.8 kg。`slack` 与 `ground` 是不同保护阈值及限幅配置，并非两种不同的吊绳状态。

| 配置 | 速度阈值 / 原始动作阈值 / 目标力矩限幅系数 | PRE 触发保护 | 播放触发保护 | POST 触发保护 | 最终通过 |
|---|---|---:|---:|---:|---:|
| `ground` | 关节速度上限的 0.8 倍 / 50 / 1.5 | 36/36 | 0/36 | 0/36 | 0/36 |
| `slack` | 关节速度上限的 0.5 倍 / 15 / 1.0 | 36/36 | 36/36 | 2/36 | 0/36 |

- **共同失败点是首次接管。** 全部 72 个工况在 PRE 第 0 步触发姿态保护，误差约 **24°–32°**。这是身体姿态误差，和之前首帧关节角差的 0.1 rad 门槛不是同一个指标。
- **继续运行后能够恢复，但不能据此忽略启动失败。** 排除 PRE 最初 5 秒后，最大姿态误差降到约 2.95°；所有工况在第 60 秒均满足脚本的播放准备条件，无额外等待。`ground` 后续播放与 POST 均无新增保护，说明稳定后的衔接较好；实际 runner 在首次 abort 时就会进入 DAMP。
- **严格配置仍有速度及衔接问题。** `slack` 全部播放工况触发速度保护，常见于左肩俯仰，另有 2 个 POST 工况触发保护。按“后续衔接力矩跳变不超过首次接管跳变的一半”的判据，`ground` 有 2/36、`slack` 有 4/36 不达标。

报告里的 `R1+X` 是评估脚本沿用的播放触发名称，不能据此认为当前 DDS 的 Start 按键映射已被测试。

## 5. 下一步建议

1. **先核对评估与当前 DDS 的支撑条件。** G3/standby 仍使用骨盆弹簧支撑，当前 DDS 仿真器已改为颈部附近受力；standby 后待机也没有恢复支撑。两者并非完全相同的流程，本次结果不能直接归因于当前 DDS 的吊绳实现。
2. **优先解决固定 PD → 策略的第一帧接管。** 在相同初始姿态与支撑条件下，核对身体姿态、首帧关节误差、关节速度和支撑释放时机，使首次接管不触发保护；不应靠放宽保护阈值或忽略前几秒来判定通过。
3. **再处理动作负载与较严格的速度限制。** 以默认/`f1.0` 为基线定位高力矩关节和时间段，针对性检查动作幅度、速度及 PD 参数；同时处理 `slack` 的肩部/膝踝速度超限，再重跑 G2、G3、standby 和实际 DDS 切换流程。

**当前结论：稳定后有完成舞蹈和策略待机的能力，但启动接管、严格速度门槛和力矩余量尚未通过，暂不足以支持直接实机完整运行。**
